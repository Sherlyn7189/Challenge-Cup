## 0. 阅读说明

本报告把 ERTM 当作一个**可独立运行、可被平台集成、可验证**的软件内核，而不是一段演示脚本。因此，“功能”不仅包括正演和成像算法，还包括模型构建、观测系统、Q 模型、数据 I/O、并行、QC、测试和文档。

需求来源：

1. 项目总任务书的十项要求；
2. 策划书技术章节中关于远探测、有限差分正演、NTFF、偶极横波成像、Q 衰减的描述；
3. 现有工程环境（Python 3.14、NumPy/SciPy/Matplotlib/Numba、`main.py` 环境自检）；
4. 同类弹性 RTM 软件的通用能力边界。

本报告不把“三维”“各向异性”“井孔流体耦合”直接放进首期 MVP，而是列为 P2 扩展。原因在功能优先级和范围边界中说明。

## 1. 项目目标与 ERTM 的功能定位

### 1.1 一句话目标

构建一个**物理自洽、可复现、可扩展**的弹性波逆时偏移（ERTM）计算内核：给定地质模型和观测系统，能够完成黏弹性正演、P/S 波场分离、PP/PS 逆时成像和可控的 Q 补偿，并输出可被处理解释人员和平台使用的成像结果与 QC 报告。

### 1.2 ERTM 在软件中的位置

ERTM 不是孤立的算法，而是未来远探测成像软件的“波场成像引擎”。它向上承接模型和观测系统，向下输出成像剖面和道集，并与现有正演、测井解释、可视化平台对接。

| 层级 | 模块 | 与 ERTM 的关系 |
|---|---|---|
| 数据层 | 模型、观测系统、子波、SEG-Y | 提供输入；ERTM 不负责采集和预处理 |
| 引擎层 | 正演、伴随、成像、Q 补偿 | **本项目核心** |
| 应用层 | 处理流程、参数扫描、QC | 调用引擎；首期只提供 CLI/API |
| 展示层 | GUI、剖面显示、解释 | 首期不做；由平台集成 |

### 1.3 三个使用层次

1. **算法研究层**：通过 Python API 和 Notebook 调用单个炮、单个模块，验证新成像条件、新 Q 模型。
2. **处理生产层**：通过 CLI 和配置文件批量跑多炮、多模型，输出剖面、道集和 QC 报告。
3. **平台集成层**：以 Python 包和稳定数据契约被外部软件调用，不依赖 GUI。

这三个层次决定了功能设计必须“模块可单独调用、流程可整体运行、数据可序列化”。

## 2. 用户角色与典型场景

| 角色 | 典型场景 | 输入 | 输出 | 成功标准 |
|---|---|---|---|---|
| 算法研究人员 | 在均匀/层状模型上验证新成像条件 | 小模型、单炮、参数配置 | 图像、波场快照、误差指标 | 结果可复现，能快速替换模块 |
| 处理解释人员 | 对合成/实际数据跑多炮成像 | 模型/数据、观测系统、Q 参数 | PP/PS 剖面、道集、QC 报告 | 界面归位准、异常体可识别、运行稳定 |
| 平台集成人员 | 把 ERTM 嵌入现有软件 | Python 包、HDF5/SEG-Y | 标准化图像和元数据 | 接口稳定、无 GUI 依赖、许可清晰 |
| 项目评审人员 | 检查是否达到任务书要求 | 文档、测试报告、基准模型 | 验收结论 | 指标可量化、结果可复现 |

典型端到端场景：

- **场景 A（算法验证）**：均匀介质 → 单炮正演 → P/S 分离 → PP/PS 成像 → 与解析解对比。
- **场景 B（构造成像）**：层状背景 + 溶洞/裂缝/断层 → 多炮正演 → 加噪 → 反传 → 叠加 → 异常体定位。
- **场景 C（Q 补偿）**：强衰减模型 → 含 Q 正演 → 反传补偿 → 与 Q=∞ 参考对比 → 振幅/频谱恢复评价。
- **场景 D（平台集成）**：外部系统传入模型和 SEG-Y → CLI 运行 → 返回 HDF5 图像和元数据。

### 3.3 端到端功能流程

1. 读取配置，校验参数；
2. 构建/加载模型，计算派生量；
3. 拟合 Q 模型，检查频带；
4. 读取观测系统，生成源/检波点；
5. 运行正演，保存记录和检查点；
6. 计算残差（有观测数据时）；
7. 反向传播，注入残差；
8. P/S 分离，形成 PP/PS 成像；
9. 归一化、Laplacian、叠加；
10. 输出剖面、道集、QC 报告；
11. 若启用 Q 补偿，重复 7—9，并输出增益曲线；
12. 保存配置快照、版本、耗时、峰值内存。

### 5.3 功能依赖关系

| 功能 | 依赖 | 被依赖 |
|---|---|---|
| 模型/参数（FR-01—06） | 无 | 正演、Q、成像 |
| 观测系统（FR-07—10） | 模型网格 | 正演、成像 |
| 正演（FR-11—15） | 模型、观测系统、Q 模型 | 伴随、成像、QC |
| 伴随（FR-21） | 正演、检查点 | Q 补偿、成像 |

**关键路径**：模型 → Q 模型 → 正演 → 伴随 → 成像 → Q 补偿。任何一环延迟，都会顺延整个首期。

### 5.4 MVP 的最小闭环

MVP 不追求“功能全”，而追求“闭环可信”。最小闭环是：

1. 一个层状模型 + 一个溶洞；
2. 一个爆炸源 + 一条测线；
3. 弹性正演 → PP 成像 → 与模型对比；
4. 加 Q → 正演 → 反传 → 补偿 → 与 Q=∞ 对比；
5. 点积测试 + 能量测试 + 界面归位测试。

只要这五步可信，后续加裂缝、断层、多炮、SEG-Y 都是工程量问题，不是原理问题。

## 7. 范围边界

### 7.1 首期纳入

- 二维各向同性弹性/黏弹性 P-SV，SH 作为独立子系统；
- GSLS 衰减与 Q 补偿；
- CPML 吸收边界，自由表面可选；
- 爆炸、单力、偶极、矩张量源；
- PP/PS/SP/SS 互相关成像；
- 层状背景 + 溶洞/裂缝带/断层尖灭；
- 合成数据正演、成像、QC、基准测试；
- Python 包、CLI、HDF5/SEG-Y 接口。

### 7.2 首期不纳入

- 三维生产性成像（只做小规模正确性验证）；
- 各向异性（VTI/HTI/TTI）；
- 井孔流体—固体耦合、套管、仪器响应；
- 起伏地表与复杂近地表；
- FWI、LSRTM、角度域成像；
- 实际资料处理与解释；
- GUI/商业软件插件；
- 数据预处理（去噪、反褶积、几何校正）。

### 7.3 边界说明

- **输入数据假设已预处理**：ERTM 不负责去噪、反褶积、切除、速度分析；这些由上游流程完成。
- **输出是深度域图像**：不做时深转换、层位解释、属性分析。
- **Q 补偿不是后处理**：它属于伴随传播，不允许做成独立滤波模块；这是功能边界，也是物理约束。
- **二维结果不等价于三维**：振幅、出平面散射、方位信息有限；报告中必须注明。

## 9. 待确认的功能性问题

以下问题会直接改变功能范围或优先级，建议在进入任务 2 前确认。

| 编号 | 问题 | 影响 | 选项 | 建议默认 |
|---|---|---|---|---|
| QF-01 | 首期面向哪种尺度：勘探尺度（10—50 Hz）还是井旁远探测尺度（0.5—5 kHz）？ | 决定网格、内存、频率、异常体尺寸，影响几乎全部功能 | A 勘探尺度；B 井旁尺度；C 两套配置 | **A 为主，B 作为第二套配置**；先锁定一套做闭环 |
| QF-02 | 首期基线是二维还是三维？ | 决定 FR-34 是否进入 MVP，影响工期和硬件 | A 二维；B 2.5D；C 三维 | **A 二维 P-SV**；2.5D/3D 放 P2 |
| QF-03 | 输入数据是纯合成记录，还是要直接读 SEG-Y 实际资料？ | 决定 FR-09、FR-14、FR-28 的优先级和复杂度 | A 合成；B 合成 + SEG-Y；C 实际资料 | **B**；首期以合成验证为主，保留 SEG-Y 接口 |
| QF-04 | 交付形态是 Python 库/CLI，还是需要 GUI？ | 决定 FR-26、FR-27、FR-32 的范围 | A 库 + CLI；B 库 + CLI + GUI | **A**；GUI 由平台集成 |
| QF-05 | 是否需要井孔流体—固体耦合？ | 决定 FR-36 是否进入首期；影响源/接收和边界 | A 不需要；B 需要 | **A 首期不需要**；用固体等效源，注明近似 |
| QF-06 | 裂缝带是否需要各向异性（HTI）？ | 决定 FR-35 和裂缝建模方式 | A 等效各向同性；B HTI | **A 首期**；HTI 放 P2，避免传播核重写 |

**建议确认顺序**：QF-01 → QF-02 → QF-03 → QF-05 → QF-06 → QF-04。前两项决定计算规模和工期，必须先定。

## 10. 结论

1. ERTM 项目首期需要实现 **6 个功能域、36 项功能**，其中 P0 23 项、P1 9 项、P2 4 项。
2. 功能闭环的关键路径是：**模型 → Q 模型 → 正演 → 伴随 → 成像 → Q 补偿**；任何一环缺失，都不能称为“可用的 ERTM”。
3. 首期 MVP 应聚焦二维 P-SV、黏弹性正演、PP/PS 成像和可控 Q 补偿；三维、各向异性、井孔流体耦合列为 P2，不在首期承诺。
4. 最容易低估的功能不是正演，而是 **Q 补偿的稳定性、伴随的正确性、P/S 分离的界面假象、以及大数据的 I/O**；这四项应在排期和风险预算中优先。
5. 目前有 6 项功能性问题待确认，其中 **应用尺度（QF-01）和二维/三维基线（QF-02）** 会直接改变功能范围和工期，建议优先拍板。
